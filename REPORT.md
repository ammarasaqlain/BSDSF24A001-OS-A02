What is the crucial difference between the stat() and lstat() system calls? In the context of the ls command, when is it more appropriate to use lstat()?
The core difference is how they handle symbolic links. stat() follows the link and returns the metadata of the target file it points to. lstat() intercepts the link and returns the metadata of the symbolic link itself. For the ls command, lstat() is strictly required. If a user runs ls -l, they expect to see the properties of the actual link sitting in that directory, not the original file hiding somewhere else on the system.

Explain how you can use bitwise operators (like &) and predefined macros to extract permission information.
The st_mode field is a bitmask—a single integer where specific binary bits act as on/off switches for different file properties. Predefined macros like S_IRUSR are just integer constants with one specific bit flipped to 1. By using the bitwise AND operator (&) between st_mode and the macro, you isolate that single bit. If the result is non-zero (True), it means that exact permission is enabled. If it is zero (False), the permission is disabled. You run this check sequentially for the owner, group, and others across read, write, and execute bits

Explain the general logic for printing items in a "down then across" columnar format. Why is a simple single loop through the list of filenames insufficient for this task?
A single loop prints sequentially from left to right (row-major order). To print "down then across" (column-major order), the program must calculate the entire grid geometry first based on the terminal width. It uses nested loops (rows, then columns) and calculates the exact 1D array index for each grid slot using the formula row + (column * total_rows). This pulls non-sequential files from the array to artificially construct vertical columns in a standard horizontal terminal printout.

The ioctl system call using the TIOCGWINSZ request dynamically hooks into the active terminal session to retrieve its exact character width. If the program relied strictly on an 80-column fallback, the output would look broken on modern monitors. Conversely, if they shrank the terminal below 80 columns, the text would visually overflow and shatter the grid alignment.

Compare the implementation complexity of the "down then across" (vertical) printing logic versus the "across" (horizontal) printing logic. Which one requires more pre-calculation and why?
The "down then across" (vertical) logic requires significantly more pre-calculation. To build vertical columns out of a flat array, the program must calculate the entire grid geometry first (total columns and rows) and then use complex index math (row + (col * num_rows)) to randomly jump through the array and extract files out of sequential order. Why is it necessary to read all directory entries into memory before you can sort them? What are the potential drawbacks of this approach for directories containing millions of files?
You literally cannot sort a stream of data while it is actively being read. The readdir() function pulls entries one at a time in whatever arbitrary order the file system stored them on the disk. To evaluate and rearrange them alphabetically, the program must have the entire dataset available simultaneously in a single array. The massive drawback to this is memory consumption; if a directory contains millions of files, dynamically allocating memory (malloc/realloc) for every single filename string will consume massive amounts of RAM and potentially crash the system if memory runs out.

Explain the purpose and signature of the comparison function required by qsort(). How does it work, and why must it take const void * arguments?
The qsort() function is a generic sorting algorithm designed to sort any data type (integers, strings, custom structs). Because it doesn't know what kind of data it is sorting beforehand, it forces the comparison helper function to accept const void * arguments (generic pointers). Inside the comparison function, you have to cast these generic void pointers back into the specific data type you are actually using (in this case, char ** for string pointers). The function then passes those strings into strcmp(), which returns a negative, zero, or positive integer to tell qsort which string belongs first alphabetically

How do ANSI escape codes work to produce color in a standard Linux terminal? Show the specific code sequence for printing text in green.
ANSI escape codes are special string sequences injected directly into standard output that the terminal intercepts instead of printing. They start with an escape character (\033 in octal), followed by a bracket [, rendering parameters, and an m to signal the end of the formatting instruction. The terminal reads this and instantly shifts the rendering style of all subsequent text until a reset code (\033[0m) is printed. The specific code sequence to print text in green is \033[0;32m

To color an executable file, you need to check its permission bits. Explain which bits in the st_mode field you need to check to determine if a file is executable by the owner, group, or others.
To determine if a file is executable, you must use bitwise AND (&) operations on the st_mode field against three specific POSIX macros: S_IXUSR (checks if the owner has execute permission), S_IXGRP (checks if the group has execute permission), and S_IXOTH (checks if others have execute permission). If the result of st_mode & (S_IXUSR | S_IXGRP | S_IXOTH) is non-zero, it means at least one of those execute bits is flipped on, classifying the file as an executable program.
